## 一、项目概述

### 1\.1 项目背景

随着文旅行业快速发展，游乐园客流量持续增长，传统线下登记、人工宣传、门票售卖模式效率低下，游客无法便捷查询游乐项目、获取园区公告，园区管理者难以统一管控游乐项目、订单、论坛信息。
为解决游乐园信息化管理需求，开发**基于 SpringBoot\+Vue 的游乐园管理系统**，系统分为**游客前台页面**与**后台管理系统**两大模块，实现游客线上浏览游乐项目、购买门票、论坛交流、打卡点赞；管理员统一维护项目信息、公告、订单、论坛、用户数据，打造一体化游乐园线上服务平台。

### 1\.2 开发技术栈

#### 后端技术

- 核心框架：SpringBoot 2\.x

- 持久层：MyBatis/MyBatis\-Plus

- 数据库：MySQL

- 开发工具：IDEA

- 构建工具：Maven

- 其他：Tomcat、Lombok

#### 前端技术

- 核心框架：Vue2/Vue3

- UI 组件库：Element UI

- 网络请求：Axios

- 路由：Vue Router

- 地图集成：百度地图 API

- 构建工具：Webpack

- 开发工具：VS Code

### 1\.3 系统目标

1. 面向游客：提供可视化游乐园门户，在线浏览游乐项目、查看园区公告、论坛发帖互动、线上购票、项目打卡点赞、地图导航；

2. 面向管理员：实现后台集中管理，对用户、游乐项目、宣传公告、论坛、门票订单、打卡信息进行 CRUD 管理；

3. 前后端分离架构，降低耦合，便于后续迭代、功能拓展；

4. 页面布局清晰，操作简单，兼顾 PC 端访问体验。

## 二、系统需求分析

### 2\.1 用户角色划分

1. **游客（普通前台用户）**
注册 / 登录系统，浏览首页、宣传公告、游乐项目；查看项目详情、点赞收藏；在线购买门票；论坛发布帖子、评论；查看项目地图导航；个人中心管理订单。

2. **系统管理员（后台用户）**
登录管理后台；管理系统用户；维护轮播图、宣传公告；管理全部游乐项目信息；审核、管理论坛帖子与评论；管理门票订单；管理游客打卡数据。

### 2\.2 功能需求

#### 前台游客端需求

1. 首页展示：轮播广告、游乐项目展示入口、导航菜单（首页、宣传公告、论坛交流、游乐项目）

2. 宣传公告模块：查看游乐园发布的公告资讯

3. 游乐项目模块

    - 项目列表：支持按名称、价格区间搜索、项目分类筛选

    - 项目详情：展示图片、名称、分类、开放时间、简介、票价、购买须知；支持点赞功能

    - 地图导航：集成百度地图，查看游乐项目地理位置、规划路线

    - 门票购买：选择项目下单，生成购票订单

4. 门票订单模块：查看个人购票记录，完成支付操作

5. 论坛交流模块：浏览帖子、发布帖子、评论他人帖子

6. 登录功能：账号密码登录入口

#### 后台管理端需求

1. 系统登录：管理员账号密码登录后台管理界面

2. 首页工作台：后台欢迎首页

3. 系统用户管理：管理平台注册游客账号信息

4. 轮播图管理：维护前台首页顶部轮播广告图片

5. 宣传公告管理：新增、修改、删除游乐园公告资讯

6. 游乐项目管理：维护游乐项目基础信息（名称、分类、开放时间、价格、图片、简介、须知等）

7. 论坛交流管理：管理全部用户帖子，查看帖子评论，新增 / 编辑 / 删除帖子

8. 门票购买管理：查看所有游客购票订单，检索订单信息

9. 打卡信息管理：查看游客游乐项目打卡记录

### 2\.3 非功能需求

1. 易用性：界面布局简洁，菜单层级清晰，符合常规网站操作逻辑

2. 可维护性：前后端分离，代码分层规范，便于后期修改新增功能

3. 稳定性：基础查询、新增、修改、删除操作稳定；分页查询防止数据加载卡顿

4. 拓展性：预留接口，后续可拓展会员、退票、评价、优惠券等功能

## 三、系统总体设计

### 3\.1 架构设计（前后端分离）

1. **前端层（Vue）**
负责页面渲染、表单交互、参数校验、页面路由，通过 Axios 发送 HTTP 请求调用后端接口，接收 JSON 格式数据渲染页面。

2. **控制层（SpringBoot Controller）**
接收前端请求，接收参数，调用业务层，向前端返回统一结果封装（成功 / 失败、响应数据、提示信息）。

3. **业务层（Service）**
编写业务逻辑，处理复杂业务规则，调用持久层完成数据库操作。

4. **持久层（Mapper/DAO）**
基于 MyBatis 实现数据库增删改查，和 MySQL 数据库交互。

5. **数据层（MySQL）**
存储系统全部业务数据。

### 3\.2 数据库主要实体设计（核心数据表）

1. **用户表 user**
存储游客账号、管理员账号；字段：id、用户名、密码、姓名、手机号、角色（管理员 / 游客）、创建时间

2. **轮播图表 banner**
id、图片地址、排序、标题、是否启用

3. **公告表 notice**
id、公告标题、公告封面图、公告内容、发布时间

4. **游乐项目表 amusement\_project**
id、项目名称、项目分类、项目图片、开放时间、项目价格、项目简介、购买须知、使用说明、费用说明、坐标位置（地图）

5. **门票订单表 ticket\_order**
id、项目 id、用户 id、购买时间、是否支付、实付价格、用户姓名、账号

6. **项目点赞表 project\_like**
id、项目 id、用户 id、点赞时间

7. **打卡记录表 project\_sign**
id、项目 id、用户 id、打卡时间

8. **论坛帖子表 forum\_post**
id、帖子标题、帖子内容、发布用户 id、发布时间、状态（开放 / 关闭）

9. **帖子评论表 forum\_comment**
id、帖子 id、评论用户、评论内容、评论时间

## 五、系统核心功能流程

### 5\.1 游客购票流程

1. 游客登录系统 → 进入游乐项目列表

2. 选择游乐项目，进入项目详情页

3. 点击【门票购买】，生成购票订单

4. 跳转订单页面，执行支付操作

5. 订单状态更新为【已支付】，完成购票

### 5\.2 游乐项目点赞流程

1. 登录游客进入项目详情

2. 点击点赞按钮；判断用户是否已点赞

3. 未点赞：新增点赞记录，点赞数量 \+ 1；

4. 已点赞：删除点赞记录，点赞数量 \- 1（取消赞）

### 5\.3 论坛交互流程

1. 登录游客进入论坛交流，发布帖子；

2. 其他游客浏览帖子，发布评论；

3. 管理员后台查看全部帖子与评论，可删除违规内容。

## 七、项目部署方案

1. **环境准备**
JDK1\.8 \+ MySQL5\.7/8\.0 \+ Maven \+ Node\.js

2. **数据库部署**
执行项目提供的 sql 脚本，创建数据库、导入数据表与初始化测试数据，修改后端配置文件 application\.yml 数据库连接信息（地址、账号、密码）。

3. **后端部署**
导入 SpringBoot 后端项目，Maven 下载依赖；启动 SpringBoot 主启动类，后端服务默认运行 8080 端口。

4. **前端部署**
进入 Vue 前端目录，执行`npm install`安装依赖；`npm run serve`本地启动前端；打包命令`npm run build`生成 dist 静态资源。

5. **访问方式**
本地运行：前端访问 [http://localhost:8081](http://localhost:8081)；
打包后可部署至 Nginx，实现公网访问。

## 八、系统优缺点与优化方向

### 8\.1 系统优势

1. 前后端分离架构，分工清晰，方便迭代开发；

2. 功能贴合游乐园真实业务，覆盖游客浏览、购票、互动、园区导航基础需求；

3. 管理员后台实现全业务数据管控；

4. 集成地图 API，提升游客园区导航体验；

5. 支持模糊搜索、区间筛选、分页查询，大数据场景下体验良好。

### 8\.2 后期优化拓展方向

1. 新增会员模块、充值、优惠券功能；

2. 增加游客项目评价、星级评分；

3. 完善图片上传 oss 云存储，替代本地存储；

4. 接入真实第三方支付接口（支付宝 / 微信）；

5. 增加数据可视化统计：售票报表、热门游乐项目统计图；

6. 增加消息通知，订单状态变更推送；

7. 实现移动端自适应（适配手机浏览器）。

## 九、总结

本**基于 SpringBoot\+Vue 的游乐园管理系统**，依托成熟前后端技术栈，搭建游客前台门户与管理员后台两大模块。系统实现游乐项目展示、线上购票、园区公告、论坛互动、地图导航、数据后台管理等核心业务。
系统解决传统游乐园信息化薄弱的痛点，打通游客线上服务渠道，帮助游乐园实现数字化运营；架构规范，代码易于维护，可在此基础上持续拓展更多文旅相关功能，具备良好实用价值与学习参考价值。
